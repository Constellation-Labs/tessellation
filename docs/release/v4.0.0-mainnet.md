## Action Required for Metagraph Operators

**This release includes breaking changes that require metagraph updates.**

The Merkle Patricia Trie (MPT) state migration changes the global snapshot format. All metagraph operators must update their metagraphs to remain compatible with the network. See [metagraph-upgrade-guide.md](metagraph-upgrade-guide.md) for detailed migration steps.

### State Proof System Transition

At the configured MainNet ordinal, the global snapshot state proof system transitions from **Legacy format** (16 individual hash fields) to **Merkle Patricia Trie format** (single MPT root hash).

- **Ordinals <= transition**: `LegacyFormat` -- `GlobalSnapshotStateProof` with 16 individual hash fields computed via Merkle tree
- **Ordinals > transition**: `MerklePatriciaFormat` -- `GlobalSnapshotStateProof` with a single `mptRoot: Option[Hash]`

Currency snapshots are not affected. `CurrencyStateProofSelector` always returns `LegacyFormat`.

### Network Validation

MPT state proofs have been validated across both Testnet (since 2026-02-06, ordinal 3,070,000) and IntegrationNet (since 2026-02-19, ordinal 5,075,000) without issue.

## What's New

### Merkle Patricia Trie (MPT) State Proofs

Cryptographic state proofs for global snapshots using Merkle Patricia Tries. This replaces the legacy 16-field hash format with a single MPT root hash, enabling efficient verification, cryptographic proofs of state inclusion, and laying the groundwork for light client support.

Key implementation details:
- `MptStore` -- interface to the trie storage (`modules/shared`)
- `FileSystemMerklePatriciaProducer` -- persistent trie producer (`modules/node-shared`)
- `StateProofSelector` / `StateProofBuilder` -- format selection and proof construction
- Incremental MPT updates (only changed fields, not entire state)
- Parallel MPT producer optimization for throughput

### Consensus Overhaul

This release includes a significant rework of the consensus subsystem:

**FSM-based architecture (#1373):** Consensus rounds are now driven by a finite state machine, replacing the previous ad-hoc coordination. This makes round transitions explicit and easier to reason about.

**Randomized facilitator selection:** Facilitators are now selected with randomization to reduce the likelihood of repeated round stalls when a particular node is slow or unresponsive. Previously, facilitator selection could get stuck cycling through the same unhealthy subset.

**Facilitator subset fixes (#1436, #1452):** Two bugs were fixed in how the facilitator subset was constructed. The first (#1436) corrected the selection logic itself. The second (#1452) fixed a case where healthy L0 peers were incorrectly removed from the facilitator candidate set, which could cause rounds to stall even when sufficient healthy peers existed.

**XOR distance bias fix (#1455):** The XOR distance calculation used for peer selection had a bias toward the most significant bit, which skewed peer distribution. This is now corrected.

**Gossip optimization (#1449):** Anti-entropy gossip has been optimized to reduce unnecessary network traffic and improve convergence time.

**Fork detection (#1365, snapshot hash):** Fork detection now uses the snapshot hash directly, making it more reliable than the previous approach.

**Cutoff application fix (#1454):** Fixed an issue with how consensus cutoffs were applied, which could lead to premature round termination.

**Peer fallback with retries (#1442):** When the preferred peer is unavailable, the system now falls back to a random peer with retry logic instead of failing immediately.

### Delegated Stakes

Incremental delegated staking activates at the configured ordinal (see table above). This allows node operators to increase existing delegated stakes without needing to withdraw and re-delegate. Includes fixes for incremental processing (#1407) and the increase feature (#1375).

### Observability

**ClickHouse structured logging (#1390, #1399):** Nodes can now emit structured logs to a ClickHouse instance for centralized monitoring and analysis. Configurable via environment variables.

**New detailed metrics (#1440):** Additional Prometheus metrics covering consensus rounds, gossip, and snapshot processing. The `/metrics` endpoint content type has also been fixed.

### Additional Changes

- **Rate limiter and route/client stream (#1361):** Adds rate limiting to HTTP routes and streaming for client connections.
- **Custom JSON codecs for serializers (#1358):** Enables custom JSON encoding/decoding for serialization, improving flexibility.
- **JSON hasher caching (#1326):** Caching layer around the JSON hasher to reduce redundant computation.
- **GL0 /token-lock endpoint:** New endpoint for querying token lock state on Global L0.
- **Owner message gate (#1450):** Enforces a gate on setting the owner message during startup on public networks, preventing accidental misconfiguration.
- **DAG transaction generator tool (#1444):** New CLI tool for load testing DAG transaction throughput.
- **Node metadata validation:** Improved validation for node metadata name and description fields.
- **Default ports for NodePilot (#1378):** Adds sensible default port configuration for NodePilot deployments.

## For Metagraph Operators

Metagraph operators must update to remain compatible. The key changes are:

1. Update Tessellation dependency to [v4.0.0-rc.10](https://github.com/Constellation-Labs/tessellation/releases/tag/v4.0.0-rc.10)
2. Update to Java 21 runtime (build, CI, and Docker images)
3. Add OSGI-INF merge strategy to `build.sbt`
4. Replace deprecated `new URL()` calls with `URI.create().toURL`

No metagraph code changes are needed for MPT -- it is handled at the global L0 layer. Metagraph snapshots continue using the existing proof format.

Full upgrade guide: [metagraph-upgrade-guide.md](metagraph-upgrade-guide.md)
