# v4.1.0-rc.9 IntegrationNet trusted recovery seed

Rc.9 is rc.8 plus an inert-by-default Global L0 recovery control for replacing
a dead rollback-anchor committee during the normal fleet-wide cold restart.

It adds no consensus message, snapshot, snapshot-info, state-proof, Kryo, or
JSON schema and changes no hashing algorithm. No metagraph activation ordinal
is required. The override is behavior-changing when armed, so deploy one
distinct immutable rc.9 version to the entire IntegrationNet fleet; never mix
rc.8 and rc.9. The existing version-string hash and deterministic consensus
configuration hash remain separate mandatory join fences.

The trusted source cohort receives:

```text
CL_GL0_RECOVERY_SEED_COMMITTEE=<peer-id-1>,<peer-id-2>,<peer-id-3>
```

Exactly one source runs `run-rollback <canonical-incremental-hash>` and every
other node runs `run-validator`. Community nodes do not receive the variable.
The authority disarms for the running JVM on its first accepted successor but
is intentionally repeatable across external starts: leaving the variable set
re-applies the same selected committee at the newly supplied canonical rollback
anchor on every later coordinated cold restart. Commenting or removing the
variable returns later launches to ordinary proof-signer seeding. It does not
pin the committee on every ordinal. No launch-role or jar symlink is changed;
later cold starts keep the normal one-`run-rollback`,
all-other-`run-validator` topology. Community release and restart automation
wait separately for the selected source proofs to establish next-seat
headroom. No cleanup jar swap or cleanup rollback is required during that
recovery invocation.

See the [trusted recovery seed runbook](../operations/global-l0-recovery-seed-committee.md)
for fail-closed checks, the exact all-member barrier, disarm semantics,
snapshot-streaming precautions, metrics, and the v35 compatibility boundary.
