# v4.1.0-rc.8 IntegrationNet consensus bridge

This release is a conservative, schema-compatible bridge from v4.1.0-rc.7 to the v35 certified-outcome protocol. It is intended for a coordinated, full-fleet IntegrationNet cold restart.

## Compatibility boundary

Rc.8 changes consensus behavior but does not change any public consensus or snapshot schema. It adds no field to a gossiped declaration, snapshot, snapshot-info value, or state proof, and changes no signed-snapshot serialization, field shape, hashing algorithm, or state-proof calculation. Consensus behavior can still produce a different valid history. Metagraphs do not need an ordinal-coordinated upgrade merely to validate snapshots produced by this release.

Rc.8 does extend the internal `ConsensusConfig` fingerprint so it binds the environment-resolved facilitator-selector cap, then wires the existing optional `consensusConfigHash` registration field into a hard L0 join fence. This changes the fingerprint value even when the effective runtime settings are otherwise unchanged. It is a cluster configuration/handshake change, not a snapshot or state-proof schema change, and needs no ordinal activation. The full fleet must nevertheless use the same rc.8 code and effective configuration.

The behavior is not safe to mix with rc.7. Every node must advertise one distinct immutable rc.8 version during the full-fleet restart. The join-time `versionHash` is the hash of the version string, optionally overridden by `CL_VERSION_HASH`; it is not an assembly hash and is independent of `deterministicConfigHash`. Never reuse rc.7's version string or version-hash override.

## Retry and view-change safety

The retry path now treats a consensus attempt as an explicit domain:

- majority signatures must match facilitator hash, parent hash, view, and proposal hash;
- Currency binary signatures must match facilitator and parent hashes, while its view-less binary/VCC/TC behavior remains exactly the rc.7 compatibility residual;
- a GL0 safe same-key retry retains only the attempt-independent Facility declarations and clears proposal/signature slots; Currency
  retains its rc.7 declaration map because the rumor layer may not retransmit already-observed values, while attempt-domain checks keep
  mismatched signatures inert;
- an asynchronous abandon request is accepted only if both the round-attempt epoch and declaration-resource epoch still match what the monitor inspected;
- abandon and view-change requests are applied on the serialized command loop, and request failures cannot terminate that loop;
- a soft reset is total and immediately re-enters scheduling only before local voting or certified view advancement. Merely accepting a proposal does not make the reset unsafe; the reset clears that attempt-bound proposal slot.

Global L0 uses `FreezeAfterVote` on the legacy wire. After this node signs an artifact, it will not emit or apply a same-key higher-view VCC/TC, nor abandon and recreate that key. The artifact signature does not authenticate admissions, evictions, responder evidence, rewards, or the other fields in the proposal envelope, so a higher-view re-vote cannot be proven safe before v35. The node keeps collecting the original attempt or converges through the existing peer-ahead download path. If neither is possible, the expected failure mode is a visible halt requiring the normal coordinated restart or the recovery-plan procedure below.

Currency L0 deliberately retains its rc.7 `PreserveLegacy` higher-view, declaration-retention, and same-key abandon/retry policy. It receives the shared attempt-domain filtering, but not GL0's post-vote freeze or Facility-only abandon cleanup. Its view-less binary phase and VCC/TC application retain the exact rc.7 compatibility behavior while its monitor remains free to abandon and retry. This residual is not the GL0 fail-closed policy and must not be described as one. It avoids silently imposing a new operator-only halt mode on metagraphs.

The legacy lock remains memory-only and artifact-only. Rc.8 narrows unsafe behavior; it does not replace v35's full-value QC or durable vote-lock journal.

## Operator-authorized Global L0 recovery

Rc.8 adds an inert-by-default `run-rollback --recovery-plan` option for an unrecoverable frozen committee. The signed local JSON plan is not a consensus message and is never embedded in a snapshot. It binds the network, exact incremental anchor ordinal/hash, designated rollback lead, and canonical committee. Startup verifies the lead signature, seedlist/allowance membership, collateral, size, and exact anchor before rollback traversal or storage mutation.

Use exactly one controlled `run-rollback` lead with the plan; every other named recovery member must start with `run-validator --recovery-plan` using the same file. Unnamed peers use normal `run-validator`. Every planned member is held behind a generation-bound local gate until all named members are in the current session and serve the exact seeded outcome. There is no timeout bypass. The plan is burned through an exclusive durable receipt and cannot be reused by a fresh process. See [Global L0 anchor-bound recovery plan](../operations/global-l0-recovery-plan.md) for the generation and incident runbook.

## Required deployment checks

1. Build and tag one immutable rc.8 artifact and verify every node advertises its distinct version hash.
2. Confirm IntegrationNet keeps `quorum-shrink-activation-views = 0`.
3. Perform the normal full-fleet cold restart; never run rc.7 and rc.8 together.
4. If using a recovery plan, stop automatic restarts, review the exact anchor and committee independently, and remove the one-shot option after recovery.
5. Before launch, verify every node reports the same effective `deterministicConfigHash`. L0 joining rejects unequal or one-sided config hashes; Facility comparison remains an additional diagnostic. This is independent of the advertised release `versionHash` fence.
6. Monitor command errors, stale abandon/view-change requests, suppressed legacy locked view changes, proof count, and `S - Q(N)` finality headroom.
7. Treat a post-vote same-key halt as the declared rc.8 safety boundary, not as permission to weaken the lock. V35 is the durable protocol fix.
