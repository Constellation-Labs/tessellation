# v4.1.0-rc.8 IntegrationNet consensus bridge

This release is a conservative, schema-compatible bridge from v4.1.0-rc.7 to the v35 certified-outcome protocol. It is intended for a coordinated, full-fleet IntegrationNet cold restart.

## Compatibility boundary

Rc.8 changes consensus behavior but does not change any public consensus or snapshot schema. It adds no field to a gossiped declaration, snapshot, snapshot-info value, or state proof, and changes no signed-snapshot serialization, field shape, hashing algorithm, or state-proof calculation. Consensus behavior can still produce a different valid history. Metagraphs do not need an ordinal-coordinated upgrade merely to validate snapshots produced by this release.

Rc.8 does extend the internal `ConsensusConfig` fingerprint so it binds the environment-resolved facilitator-selector cap, then wires the existing optional `consensusConfigHash` registration field into a hard L0 join fence. This changes the fingerprint value even when the effective runtime settings are otherwise unchanged. It is a cluster configuration/handshake change, not a snapshot or state-proof schema change, and needs no ordinal activation. The full fleet must nevertheless use the same rc.8 code and effective configuration. On the v35 follow-on branch, the same resolver also binds the scheduled certified-consensus activation key without changing that separately announced ordinal boundary.

The behavior is not safe to mix with rc.7. Every node must advertise one distinct immutable rc.8 version during the full-fleet restart. The join-time `versionHash` is the hash of the version string, optionally overridden by `CL_VERSION_HASH`; it is not an assembly hash and is independent of `deterministicConfigHash`. Never reuse rc.7's version string or version-hash override.

## Retry and view-change safety

The retry path now treats a consensus attempt as an explicit domain:

- majority signatures must match facilitator hash, parent hash, view, and proposal hash;
- Currency binary signatures must match facilitator and parent hashes, while its view-less binary/VCC/TC behavior remains exactly the rc.7 compatibility residual;
- a GL0 safe same-key retry retains only the attempt-independent Facility declarations and clears proposal/signature slots; Currency
  retains its rc.7 declaration map because the rumor layer may not retransmit already-observed values, while attempt-domain checks keep
  mismatched signatures inert;
- an asynchronous abandon request is accepted only if both the round-attempt epoch and declaration-resource epoch still match what the monitor inspected;
- abandon and view-change requests are applied on the serialized command loop, and request failures cannot terminate that loop;
- a soft reset is total and immediately re-enters scheduling only before local voting or certified view advancement. Merely accepting a proposal does not make the reset unsafe; the reset clears that attempt-bound proposal slot.

The sole `RestartAfterSoftReset` wake-up is now failure-total as well. Ancillary latch and telemetry
failures cannot consume it. If dispatch fails, recovery probes the serialized consensus state:
absent state releases a Busy FSM and schedules a new round only while the node is `Ready`; present
state is preserved and its monitor is re-armed; an inconclusive probe mutates nothing and retries the
same command after a bounded delay. A stale restart can therefore neither erase declarations that
rebuilt the round nor leave an empty key permanently Busy.

Global L0 uses `FreezeAfterVote` on the legacy wire. After this node signs an artifact, it will not emit or apply a same-key higher-view VCC/TC, nor abandon and recreate that key. The artifact signature does not authenticate admissions, evictions, responder evidence, rewards, or the other fields in the proposal envelope, so a higher-view re-vote cannot be proven safe before v35. The node keeps collecting the original attempt or converges through the existing peer-ahead download path. If neither is possible, the expected failure mode is a visible halt requiring the normal coordinated restart or the recovery-seed procedure below.

Historical rc.8 only: Currency L0 retained its rc.7 `PreserveLegacy` higher-view,
declaration-retention, and same-key abandon/retry policy. The v35 release branch has since
replaced that experimental Currency path with the release/mainnet-style flat synchronous
all-member engine documented in
[`currency-l0-synchronous.md`](../consensus/currency-l0-synchronous.md). Do not use this
rc.8 bridge note to infer current Currency behavior.

The legacy lock remains memory-only and artifact-only. Rc.8 narrows unsafe behavior; it does not replace v35's full-value QC or durable vote-lock journal.

## Sustained admission headroom

Rc.8 retains rc.7's GL0 signing leases and does not restore automatic silent-seat shedding. It
closes the observed grow-then-wedge oscillator by strengthening only local admission-vote emission:

- a floor-neutral admission keeps the existing one-parent behavior;
- an admission batch that raises `Q(N)` must be supported by at least `Q(N + A)` current-committee
  proofs on each of the last three consecutive finalized parents;
- the bounded history contains actual locally observed snapshot proof sets, resets on a lineage
  change or explicit download/rollback initialization, permits signer identities to rotate, and
  ignores proofs from outside the current committee;
- both open expansion and probation recovery obey the floor-step invariant, while probation retains
  its separate cadence, direct-probe, streak, and penalty semantics;
- the history controls vote/abstain only. It is absent from proposals, certificates, outcomes,
  snapshots, configuration hashes, and state proofs. Existing Core-quorum admission certificates
  for open expansion, and the existing wider recovery-witness certificates for probation, remain
  the sole membership authority.

This is intentionally conservative after restart: three new finalized parents must be observed
before a floor-raising admission can receive this node's vote. It adds no reward-population cap;
growth continues whenever sustained existing participation proves the next denominator safe.

This gate prevents admission from creating an immediately necessary signer; it is not a silent-seat
self-heal protocol. Rc.8 still performs no automatic health-derived eviction. If retained silent seats
drive observed participation below `Q(N)`, the network intentionally halts instead of shrinking a
node-local denominator. Recovery then requires ordinary convergence/restart or the trusted recovery
seed below. V35 remains the durable certified-outcome path; do not describe the admission gate as a
replacement for it.

## Finalization-effect recovery boundary

Rc.8 retains each exact post-transition Facility, Proposal, and Finished side effect until it succeeds.
Dynamic Facility inputs and the selected proposal certificate envelope are captured before the state
commit; the leader self-stores that exact Proposal before transport. Snapshot persistence accepts an
exact-current replay as a repair, preserves the originally accepted context, and propagates required
snapshot-info failures. Currency state-channel binary capacity now backpressures finalization while the
independent queue worker drains rather than dropping a hash-linked binary.

These retained effects are process-local. They close operational failure and cancellation gaps inside a
running JVM, but they are not a durable outbox across a process crash. The vote lock and Currency binary
tracker are likewise memory-only; data-application notification is at-least-once at its cancellation
boundary, and the GL0 peer-history sidecar remains best-effort after the outcome CAS. A crash in those
windows must use the existing storage/download recovery paths. This is an explicit rc.8 boundary, not a
new public schema or state-proof contract.

## Operator-authorized Global L0 recovery

The final bridge uses only `CL_GL0_RECOVERY_SEED_COMMITTEE` on the selected
controlled source cohort. There is no separate recovery file, generator,
receipt, CLI option, or private artifact to distribute. The selected nodes bind
the env committee to the exact validated public incremental anchor, seedlist,
allowance list, collateral, configured size, and next-seat viability before
rollback mutation. Every selected member then holds every round-start trigger
until the entire named cohort serves the exact same synthetic outcome. See the
[trusted recovery seed runbook](../operations/global-l0-recovery-seed-committee.md).

## Required deployment checks

1. Build and tag one immutable rc.8 artifact and verify every node advertises its distinct version hash.
2. Confirm IntegrationNet keeps `quorum-shrink-activation-views = 0`.
3. Perform the normal full-fleet cold restart; never run rc.7 and rc.8 together.
4. If using the recovery env, stop automatic restarts, review the exact anchor and committee independently, and remove the env after the first successor without restarting the running cohort.
5. Before launch, verify every node reports the same effective `deterministicConfigHash`. L0 joining rejects unequal or one-sided config hashes; Facility comparison remains an additional diagnostic. This is independent of the advertised release `versionHash` fence.
6. Monitor command errors, stale abandon/view-change requests, suppressed legacy locked view changes, proof count, `S - Q(N)` finality headroom, and the sustained-admission history/qualification gauges.
7. Treat a post-vote same-key halt as the declared rc.8 safety boundary, not as permission to weaken the lock. V35 is the durable protocol fix.
