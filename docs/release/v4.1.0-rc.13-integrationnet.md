Status: reviewed pre-deploy candidate. Pushing creates the release tag and draft; publish the
advance notice only after the tagged artifacts are available. The later operational items are
activation and follow-up checks, not prerequisites for pushing the candidate branch.

## Source represented by this candidate

The release branch merges the reviewed `develop` tree containing PR #1566 plus all
post-rc.12 fixes already merged before it:

- Global L0 v35 certified outcomes, persistent vote locks, authenticated committee
  transitions, certified download/replay validation, and activation-parent retention;
- restoration of Currency L0 to the flat synchronous release/mainnet-style engine;
- Currency signed-history protocol `1.0.0`, durable state-channel binary outbox, and
  deterministic dormant-lineage resurrection support;
- checked per-transaction fee arithmetic and the exact authorized Pacaswap balance
  adjustment artifact;
- replay-gated complete data-application fee validation and allow-spend escrow semantics;
- prevention of inter-round and same-round allow-spend double settlement;
- Snapshot Streaming compatibility updates, ClickHouse appender packaging, and the
  reviewed npm dependency updates;
- release automation pinned to immutable action commits and release-tool version
  `13.1.2`, with artifact assembly/signing completed before the tag is pushed and
  IntegrationNet releases marked as prereleases.

## Behavior at the cold restart

The release/version and deterministic-config fences become effective as soon as the
coordinated fleet starts. In particular, the Currency L0 flat synchronous engine is a
jar-level behavior change; it is not enabled by the later Currency protocol ordinal.
Do not mix rc.12 and rc.13 nodes within any Global or Currency L0 cohort.

The checked fee-transaction arithmetic uses the historical IntegrationNet replay
boundary `5,905,000`. That value must not be moved to the new activation ordinal:
history at or below it retains the deployed wrapping path, while later eligible
Currency history uses checked debit and credit operations.

## Behavior at Global ordinal 5,923,000

| Gate | Effect |
|---|---|
| `snapshot.certified-consensus-activation-ordinal.integrationnet` | Global L0 begins v35 certified-outcome semantics. |
| `fields-added-ordinals.currency-snapshot-protocol-v1.integrationnet` | An eligible Currency lineage may advance its signed snapshot version from `0.0.1` to `1.0.0`. |
| `fixing-data-application-fee-validation.integrationnet` | Currency data application acceptance validates every fee and rejects a block whose fee cannot be applied. |
| `fixing-allow-spend-destination-credit.integrationnet` | Historical recreation becomes single-mode escrow semantics at and after the boundary. |
| `preventing-allow-spend-resurrection.integrationnet` | The retired-reference ledger and same-round consumption protection apply when the evaluated Global dependency is greater than the configured boundary. |
| `fixing-global-allow-spend-expiration.integrationnet` | A consumed expired Global allow-spend is not both refunded and settled. |

These are separate configuration fields even though this release intentionally gives
them one announced Global ordinal.

The data-fee, destination-credit, and expired-spend corrections use inclusive
comparisons and first apply at `5,923,000`. Anti-resurrection intentionally compares
the evaluated Global dependency strictly above the boundary, so its first effective
ordinal is `5,923,001`.

## Compatibility and operator action

- Stop the complete active GL0 fleet and restart it on one exact artifact.
- Rebuild Currency L0, Currency L1, and every Data L1 application against the exact
  `v4.1.0-rc.13` SDK. A dependency-only edit is not sufficient compatibility evidence.
- Upgrade every active Currency cohort completely before ordinal `5,923,000`.
- Audit each active lineage's signed `unappliedGlobalChangeOrdinals`. Hold activation
  if required history cannot be proven or drained.
- Keep dormant, unknown, and legacy metagraph producers offline until rebuilt and
  individually cleared through the documented resurrection procedure.
- Treat `BaseDataApplicationL0Service.onSnapshotConsensusResult` as at-least-once.
  Application callbacks must be idempotent by snapshot hash or ordinal-plus-hash.
- Deploy and record the independently built Snapshot Streaming artifact using this
  exact SDK before the activation boundary.

## Deliberately excluded or dormant

- The fork-recovery E2E remains disabled by release decision. The staged, crash-safe v2
  same-prefix recovery design and arbitrary historical-LCA receipts are not part of
  this candidate.
- Existing rc.12 recovery behavior is unchanged: sustained divergence and liveness
  triggers can still move a node into incremental download recovery. This is not the
  deferred v2 mechanism and must not be described as though all automatic recovery is
  disabled. If the release decision is to disable runtime recovery as well as the E2E,
  stop: every recovery trigger needs an explicit gate and regression coverage.
- IntegrationNet quorum-denominator shrink remains disabled (`0`).
- Testnet and Mainnet v35/Currency-v1 gates remain unscheduled.
- Currency synchronous ACK contraction retains the trusted, small-committee threat
  model inherited from release/mainnet. A Byzantine signer that equivocates can split
  local reduced committees; this candidate does not claim Byzantine-fault tolerance for
  privately operated Currency L0 committees.
- Event Gossip count and response-size bounds are present, but request-body limiting
  still occurs after HTTP decoding in this candidate. A pre-decode entity limit remains
  a defense-in-depth follow-up.

## Tooling security findings

On 2026-09-01, root `npm audit` reported 24 findings (7 low, 12 moderate,
3 high, 2 critical); `--omit=dev` reported 22 (7 low, 11 moderate, 2 high,
2 critical). The `.github/action_scripts` lockfile reported 23 findings (6 low,
12 moderate, 3 high, 2 critical) both with and without development dependencies.
These packages support repository CI/E2E transaction clients and are not packaged in
the four JVM release assemblies. A trial non-breaking root `npm audit fix` caused
broad `dag4`/lockfile churn and still retained both critical findings, so do not apply
it mechanically in this candidate. Remediate both legacy `dag4` dependency graphs in
a separate tested change and do not expose long-lived production keys to these scripts.
