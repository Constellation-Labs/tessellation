# v4.1.0-rc.12 IntegrationNet first-round alignment

Rc.12 is rc.11 plus one schema-compatible Global L0 cold-start behavior
change. It aligns the anchor proof-signer committee before the first round so a
staggered full-fleet startup cannot split that committee across independent
view timers.

It adds no consensus declaration, snapshot, snapshot-info, state-proof, Kryo,
JSON, codec, hashing, or configuration field. No metagraph activation ordinal
is required. It is still a consensus behavior change: deploy one distinctly
advertised rc.12 version to the complete IntegrationNet fleet in the normal
cold restart. Do not mix rc.11 and rc.12.

For normal post-bootstrap rollback:

- the rollback lead must be in the selected incremental anchor's proof signer
  set;
- only exact, current-session members of that set count;
- the lead waits for the configured `Q(N)` with no timeout escape;
- committee validators remain held until an existing validated Facility pulse
  establishes one start edge;
- unrelated Ready peers cannot satisfy the barrier; and
- exact expected/derived committee equality is enforced before consensus state
  or the first Facility effect commits.

True bootstrap and Currency L0 are unchanged. A signed recovery plan or
`CL_GL0_RECOVERY_SEED_COMMITTEE` takes precedence and retains the existing
exact all-member barrier.

Before stopping the fleet, verify that the one controlled `run-rollback` lead
appears in the chosen anchor's proofs. Disable automatic restarts through the
first successor. While
`dag_consensus_normal_first_round_alignment_held == 1`, a flat tip is an
intentional **DO-NOT-RESTART** condition, not a stall.

See the [full first-round alignment runbook](../operations/global-l0-first-round-alignment.md)
for the algorithm, failure behavior, metrics, recovery-seed composition, and
v35 forward-port requirement.
