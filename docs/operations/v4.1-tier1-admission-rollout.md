# v4.1 Tier-1 admission and finality-audit rollout

This runbook covers the Global-L0 broad Core + Tier-1 signing/reward committee,
five-round proactive admission cadence, exact one-parent and sustained admission
headroom policy, and proof-based participation hysteresis introduced with ADR-0030.
It also covers the recovery outcome-storage alignment in ADR-0031.

ADR-0030's v34 Tier-1-only standalone-eviction bridge is historical below the v35
activation key. Once ADR-0032 certified consensus is active, the audit covers every
Core + Tier-1 signing seat and may only produce an exact one-for-one atomic
replacement: one silent-seat ECS paired with one open ReadyAtTip ACS in the same
certified ProposalValue. A standalone or unequal health-derived eviction batch fails
closed. The v35 path never shrinks the signing roster through this health-derived
policy. Separate deterministic eligibility and administrative authority (seedlist,
next-context/on-chain collateral eligibility, and configured facilitator selection)
remains unchanged and can still remove an ineligible incumbent.

The rc.7/rc.8 IntegrationNet bridge runs Global L0 with `RetainSigningLeases`:
all automatic health-derived eviction emission, proposal inclusion, validation, and
apply paths are disabled before certified activation. It deliberately prefers a
visible halt plus operator recovery over another node-local shedding ratchet. The v35
atomic replacement lane is separate and only becomes active at its announced
`certified-consensus-activation-ordinal`.

Neither version changes Global Incremental Snapshot, Global Snapshot Info, Global
Snapshot State Proof, state-proof calculation, or passive metagraph snapshot
validation. V34 adds no activation ordinal beyond its scheduled feature gates. V35
does change the active consensus envelope; see the ADR-0032 rollout runbook. Every
deployment remains a full coordinated cold restart with one advertised version, one
jar, and one consensus configuration across the cluster. Do not stage or canary
different jars inside the live cluster.

## Protocol expectations

- Core remains the leader and liveness-certificate cohort.
- Core + Tier 1 is the frozen signing committee and, once
  `delegated-rewards-full-committee` is active, the delegated validator-reward set.
- Open Ready-at-tip growth has no fixed population cap. With the shipped settings it
  can add at most one seat every five rounds.
- Penalty/probation readmission remains available every round and does not wait for
  the open cadence, but it shares the same
  one-parent and sustained-signing headroom checks when the accepted batch would raise
  the finality floor. A floor-neutral probation recovery remains immediate. Before
  certified atomic membership activates it uses the existing wider witness lane;
  under certified membership, Core must certify every admission-only change.
- Countdown zero remains part of the probation lane until a certificate is accepted.
  If open and probation certificates compete for the one-certificate proposal budget,
  probation recovery has priority. The node-local operational sidecar preserves zero-entry
  membership through its existing integer field; the signed artifact's evidence-only
  `peerHistory.perPeer` remains empty and unchanged.
- A probation certificate may clear the target's carried `penaltyUntil` horizon.
  Applying that horizon as a validation blocker to the same recovery certificate
  would make readmission circular; non-probation/open targets remain penalty-blocked.
- A Global-L0 Core node emits an open or probation vote for a floor-raising batch only
  when its locally observed parent proofs from current committee members satisfy:

  ```text
  observed current-committee parent signers >=
    finality floor(current committee size + 1)
  ```

  Example: six seats have a four-signature finality floor, but seven seats require
  five. Four observed current-member proofs pause both admission lanes; five can
  satisfy the one-parent check.
- A floor-raising batch additionally needs that exact next-size floor on three
  consecutive finalized parents, reusing
  `TierTransitions.DemotionConsecutiveMisses`. Signer identities may rotate between
  those parents; each proof set is independently intersected with the current
  committee. A floor-neutral batch does not wait for this history. Re-observing one
  parent is idempotent; an ordinal gap, same-ordinal hash replacement, download, or
  rollback starts a fresh local history and therefore delays the next floor-raising
  vote rather than inheriting evidence from an abandoned lineage.
- The proof-subset headroom decision is local. It never rejects a proposal and never
  enters committee/state derivation. A new seat still requires a Core-quorum
  AdmissionCertificate.
- During legacy bootstrap, a batch that remains below
  `bootstrapCompleteProofsThreshold` bypasses both local headroom checks so a singleton
  can grow. The threshold-crossing batch is gated because it can activate the
  full-committee finality floor immediately. Under v35, every round uses the frozen
  full-committee floor, so the headroom gate remains active even if the legacy
  proof-size window still reports bootstrap.
- Under v35, every node tracks actual local parent-proof misses for every auditable
  Core + Tier-1 signing peer. A Core node emits the selected target's eviction vote
  only after three consecutive misses spanning at least two configured
  `timeTriggerInterval` periods, and only in the exact dead band where the current
  committee remains finalizable but one additional seat is unsupported. Any observed
  proof resets both the round and elapsed-time streak. Restart, missing parent evidence,
  or a non-consecutive parent ordinal clears the local history, delaying replacement.
  The audit reuses the five-round open-membership cadence.
- Membership has three exact v35 states. If observed signers satisfy the next-seat
  floor, open expansion may proceed. If they satisfy the current floor but not the
  next-seat floor, one hysteresis-qualified silent seat may be replaced one-for-one by
  an open ReadyAtTip peer. Below the current floor, the health-derived path makes no
  membership change. It cannot rescue a committee that no longer has the frozen Core
  quorum required to certify the pair.
- The ECS and ACS are independently tip-bound, committee-bound, and Core-quorum
  certified, then certified together in ProposalValue. The admission target cannot be
  the eviction target or a probation target. Proposal construction and validation cap
  and enforce equal cardinality; neither certificate has standalone replacement
  authority on Global L0 v35.
- Outside bootstrap, finality remains the supermajority floor of the complete frozen
  Core + Tier-1 committee. The audit does not lower the current-round floor and cannot
  recover a committee that is already unable to finalize.

## Before the restart

1. Record the release tag, advertised version hash, assembly checksum,
   `consensusSchemaVersion` (34 below v35, 35 for the certified-consensus release),
   resolved `deterministicConfigHash`, activation key, and target environment.
2. Verify the packaged Global-L0 values match on every node. In particular:
   `active-admission-max-expansion-per-round = 1` and
   `active-admission-expansion-interval-rounds = 5`.
3. Record the current tip and the status of every existing fields-added ordinal. This
   change adds no ordinal, but it does not defer or replace the scheduled v4.1 gates.
4. Capture a byte-identical agreed checkpoint and the normal operational backups
   required by the coordinated-restart procedure. Keep this as the rollback boundary.
5. Capture a pre-restart baseline over enough rounds to include at least two five-round
   cadence boundaries:
   - Core, Tier-1, Witness, and total frozen committee sizes;
   - final proof count, actual required count, and round duration;
   - view changes and admission-certificate build success/failure logs;
   - Ready peer count;
   - delegated reward-recipient count, with the full-committee reward gate status
     recorded beside it.
6. Disable automated restarts, stop every Global-L0 JVM, and follow the source/priority
   startup ordering in `docs/release/v4-launch-runbook.md`.

## Post-restart verification

First verify cluster agreement before interpreting growth:

1. Every Global-L0 node reports the same release/config hash and reaches `Ready`.
2. Nodes agree on snapshot ordinal and artifact hash. Metagraphs continue advancing
   without a state-proof implementation update.
3. The chain finalizes normally through startup. Do not diagnose admission behavior
   from the initial bootstrap/recovery rounds.

Then observe at least two open-admission cadence opportunities. This is an observation
checkpoint, not a committee-size cap.

### Finality metrics

| Metric | Expected meaning |
|---|---|
| `dag_consensus_signature_committee_size` | Frozen Core + Tier-1 denominator for the round. |
| `dag_consensus_signature_first_quorum_count` | Valid proofs present when this node first observed finalizability. |
| `dag_consensus_signature_required_count` | Actual finality requirement. Outside bootstrap this is the full frozen-committee floor, not Core strict majority. |
| `dag_consensus_signature_finality_margin` | `first quorum count - actual required count`. It must never be negative when finality is reported. |

### Open-admission metrics

| Metric | Expected meaning |
|---|---|
| `dag_consensus_open_admission_cadence_allowed` | `1` only on ordinals allowed by the existing interval. |
| `dag_consensus_open_admission_observed_current_committee_signers` | Parent proof signers after intersection with the current committee. |
| `dag_consensus_open_admission_next_committee_size` | Current frozen committee plus exactly one proposed open seat. |
| `dag_consensus_open_admission_next_finality_floor` | Exact configured finality floor for that next size. |
| `dag_consensus_open_admission_finality_margin` | Observed current-member signers minus the next-size floor. Negative pauses open voting. |
| `dag_consensus_open_admission_vote_allowed` | Combined cadence and headroom decision. |
| `dag_consensus_probation_admission_vote_allowed` | Headroom decision for the cadence-independent probation lane. It is `0` when a floor-raising recovery lacks either one-parent or sustained headroom. |
| `dag_consensus_open_admission_headroom_gate_active` | `1` when the local next-seat headroom gate is being evaluated: at/after the bootstrap threshold-crossing batch, or outside bootstrap. |
| `dag_consensus_open_admission_sustained_gate_active` | `1` when the candidate batch raises the finality floor and therefore needs consecutive-parent evidence. |
| `dag_consensus_open_admission_sustained_history_depth` | Number of consecutive finalized parents currently retained, capped at three. |
| `dag_consensus_open_admission_sustained_history_required` | Required consecutive-parent count (currently three). |
| `dag_consensus_open_admission_sustained_qualifying_parents` | Retained parents whose current-committee proof count reaches the proposed next-size floor. |
| `dag_consensus_open_admission_sustained_vote_allowed` | `1` when the sustained gate is absent, floor-neutral, or fully qualified. |
| `dag_consensus_open_admission_policy_total{outcome=...}` | Decision counter: `off_cadence`, `insufficient_headroom`, `insufficient_sustained_headroom`, `allowed`, `bootstrap_cadence_only`, or Currency's `cadence_only` path. |

The structured admission gate log also reports `openCadenceAllowed`,
`openObservedSigners`, `openNextFinalityFloor`, `openFinalityMargin`,
`probationVoteAllowed`, `sustainedHistoryDepth`, `sustainedHistoryRequired`, and
`sustainedQualifyingParents`. Certificate
assembly success is logged as `assembly=quorum_reached_cert_stored`; failures use
`assembly=acs_build_failed`. An off-cadence open certificate must never enter an
accepted proposal. A probation certificate may do so on any round only when the
shared denominator-safety gates allow it.

### Signing-finality replacement metrics

`dag_consensus_signing_finality_audit_total{outcome=...}` distinguishes:

- `signature_observed`: the selected target signed and its streak is reset;
- `round_hysteresis_wait`: locally missed, but fewer than three consecutive misses;
- `duration_hysteresis_wait`: three misses occurred too quickly to span the configured
  elapsed-time floor;
- `vote_emitted`: the count, elapsed time, dead-band headroom, and cadence all
  qualified, so this Core node emitted the ECS half of a possible replacement;
- `headroom_preserved`: the miss streak qualified, but the observed signer population
  can safely support one additional seat, so open expansion is preferred;
- `below_current_floor`: the current committee is already below its finality floor,
  so health-derived replacement fails closed;
- `off_cadence`: an otherwise-qualified atomic replacement abstained until the next
  existing membership-change cadence opportunity;
- `already_voted`: the round-local vote already exists;
- `missing_parent_evidence`: history was cleared instead of inferring a miss;
- `error`: the audit failed open and the round continued.

The `stage=signing_finality_audit` and `stage=signing_finality_audit_suppressed` logs
include miss count and duration, current committee size/floor/margin, next-seat
floor/margin, cadence eligibility, and the suppression outcome.

| Metric | Expected meaning |
|---|---|
| `dag_consensus_signing_finality_audit_current_committee_size` | Current Core + Tier-1 signing committee used for the local decision. |
| `dag_consensus_signing_finality_audit_observed_current_committee_signers` | Locally finalized parent proofs intersected with that committee. |
| `dag_consensus_signing_finality_audit_current_finality_floor` | Exact finality floor for the committee already seated. |
| `dag_consensus_signing_finality_audit_current_finality_margin` | Observed signers minus the current-seat floor. A negative value fails replacement closed. |
| `dag_consensus_signing_finality_audit_next_committee_size` | Current committee plus exactly one seat. |
| `dag_consensus_signing_finality_audit_next_finality_floor` | Exact finality floor for one additional seat. |
| `dag_consensus_signing_finality_audit_finality_margin` | Observed signers minus the next-seat floor; retained for admission/headroom dashboard compatibility. |
| `dag_consensus_signing_finality_audit_membership_hold` | Legacy-named dead-band gauge: `1` when the current floor is met but the next-seat floor is not. Under v35 this is the only headroom state permitting an N-to-N replacement. |
| `dag_consensus_signing_finality_audit_cadence_allowed` | `1` only on the existing membership-change cadence. |
| `dag_consensus_signing_finality_audit_atomic_replacement_allowed` | `1` only in the current-floor-to-next-floor dead band; count, time, cadence, exact intent, paired ReadyAtTip ACS, and both quorums must still qualify. |
| `dag_consensus_readmission_probation_size` | All probation map entries, including countdown zero. |
| `dag_consensus_readmission_probation_ready_size` | Sticky probation entries at countdown zero, awaiting certified recovery. |

On rc.8 Global L0, expect
`dag_consensus_tier1_finality_audit_total{outcome="disabled_by_membership_policy"}` and zero
new eviction certificates applied. Any active automatic-eviction signal is a rollout blocker because
it implies a node is not running the intended bridge policy.

## Health-dependent growth checks

Do not choose an arbitrary target size or override a headroom pause. Growth is healthy
when all of the following hold across cadence opportunities:

- open certificates occur only on cadence and add no more than the configured one
  open seat;
- the next-seat headroom margin is non-negative on nodes that vote;
- proof count and actual finality requirement grow together without a sustained rise
  in view changes or round duration;
- `acs_build_failed reason=under_quorum` is no longer the dominant admission outcome;
- signing-finality audit votes appear only after round and elapsed-time hysteresis,
  on cadence, and only in the dead band. Every accepted health-derived ECS is paired
  one-for-one with an open ReadyAtTip ACS; standalone eviction and cardinality drift
  remain zero;
- Ready peers that remain healthy progressively enter Tier 1 instead of the committee
  ratcheting back to Core-only size.

Reward breadth must be interpreted against the activation gate. Before
`delegated-rewards-full-committee`, the historical legacy recipient filter still
applies. At and after the gate, compare delegated validator recipients with the frozen
Core + Tier-1 committee; Witnesses are intentionally excluded.

## Stop and rollback conditions

Stop expansion investigation and prepare a coordinated rollback if nodes disagree on
artifact/state-proof validation, the reported required count differs for the same
round, an off-cadence open certificate is accepted, a v35 standalone/unequal
health-derived eviction batch is accepted, or the chain develops sustained
view-change/round-duration degradation as committee size increases.

For rollback:

1. Disable automated restarts and stop the full Global-L0 cluster.
2. Restore the previous jar and its matching consensus configuration everywhere.
3. Resume from the agreed pre-cutover checkpoint captured above. Do not ask the old
   behavior to replay and continue a post-cutover committee history whose admissions
   or evictions it would have decided differently.
4. Bring source/priority peers to `Ready`, then the remaining peers, and confirm a
   single artifact hash before re-enabling automation.

No metagraph software rollback is required solely because of the unchanged global
snapshot/state-proof calculation, but normal cross-layer checkpoint coordination still
applies.

## Recovery handoff verification

During incremental recovery, the specific consensus-outcome request can return HTTP
Conflict after the cluster advances beyond the downloaded ordinal. The client then
fetches the latest outcome. Before that newer outcome is installed into consensus,
Global L0 must align `LastNGlobalSnapshotStorage`, `LastSnapshotStorage`, snapshot head,
and MPT state to the accepted artifact/context and remove any newly observed mempool
events already committed by it.

Monitor `dag_consensus_download_newer_outcome_storage_aligned_total` and the structured
`stage=newer_outcome_storage_aligned` log. A subsequent non-contiguous snapshot-storage
error is a rollout blocker; its message now includes both current and incoming ordinal
and hash. A DownloadDaemon `aborting retry loop` line is not independently evidence of
a failed recovery: queued state events can be cancelled immediately after a successful
`RecoveryDownload Converged` handoff. Correlate timestamps and ordinals before assigning
causality.
